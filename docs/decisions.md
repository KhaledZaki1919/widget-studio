# Decisions (ADR log)

Short records of decisions that shape the code. Newest last. The locked product decisions D1–D9 are in `widget-app-brief.md` §0; the ADRs below record them and add the engineering decisions.

### ADR-001 — Product decisions from the brief (D1–D9)
**Status:** Accepted (2026-10-20).
- **D1** iOS first, native Swift / SwiftUI, iOS 17+ (interactive widgets via AppIntents, `containerBackground`). Android (Kotlin + Glance) later, same spec.
- **D2** No Mac. All iOS builds, tests and IPA packaging run on GitHub Actions macOS runners. The repo is public (free Actions minutes), so a secret scan must pass before every push.
- **D3** Distribution: unsigned IPA from CI → Sideloadly → owner's iPhone with a free Apple ID (7-day re-sign, max 3 apps, 10 App IDs per week; app + widget = 2). Nothing that blocks App Store review later.
- **D4** Bring-your-own-key AI: Gemini (default, free key), Anthropic, OpenAI, OpenRouter. Key in the Keychain.
- **D5** No backend in v1. Templates are bundled.
- **D6** AI returns a JSON spec, never code; validated on device before rendering.
- **D7** Arabic (default) + English, full RTL.
- **D8** No accounts, no sync, no analytics. Data stays in the App Group container.
- **D9** Bundle ID `com.khaled.widgetstudio`, widget `com.khaled.widgetstudio.widgets`, App Group `group.com.khaled.widgetstudio`.

Open questions use the brief's defaults: name "Widget Studio", Android after iOS ships, free, lock-screen widgets in v1.1.

### ADR-002 — Project generated by XcodeGen
**Status:** Accepted (2026-10-20).
**Context:** No Mac to click through Xcode; `.pbxproj` merges are unreadable.
**Decision:** `ios/project.yml` is the source of truth. CI runs `xcodegen generate`. The `.xcodeproj` and generated `Info.plist`s are gitignored. Entitlements files are written by XcodeGen from `entitlements.properties` on every generate. Targets: `WidgetStudio` (app), `WidgetStudioWidgets` (widget extension), `WidgetStudioUITests` (smoke), plus the local Swift package `WidgetKitCore`, whose unit tests run with `swift test`.

### ADR-003 — Unsigned IPA from CI, ad-hoc signed for entitlements
**Status:** Accepted (2026-10-20). Same as Lakhas ADR-012.
**Decision:** CI builds Release for `iphoneos` with `CODE_SIGNING_ALLOWED=NO`, then `ios/scripts/build-ipa.sh` ad-hoc signs (`codesign --sign -`, no certificate, no secret) the widget extension first and then the app with their entitlements, so Sideloadly can see the requested App Group (and HealthKit). The script fails if either bundle lacks the App Group entitlement, if `UILaunchScreen` is missing, or if a secret-like string is in the bundle. The IPA is uploaded as artifact `WidgetStudio-ipa`, kept 30 days.

### ADR-004 — Runtime App Group resolution (free Apple ID fallbacks)
**Status:** Accepted (2026-10-20); behavior on device to be confirmed by the M0 Diagnostics report.
**Context:** In Lakhas, a free-Apple-ID Sideloadly install reported no App Group in the signing profile; Sideloadly lists custom entitlements as a paid feature. Signers that do support groups may rewrite the group ID.
**Decision:** Ported from Lakhas ADR-014. App and widget resolve the shared container at runtime:
1. `ALTAppGroups` from Info.plist. AltStore/SideStore register these groups on free accounts and rewrite the key to the real IDs when signing (added 2026-10-20, after the M0 device test);
2. App Groups in `embedded.mobileprovision` (as rewritten by the signer);
3. the compiled ID from Info.plist (`WSAppGroup`);
4. the target's own container (not shared). The widget then shows "Open the app to set up widgets".

The first candidate whose container is writable wins. `StoreLocation.source` records which step it came from. Diagnostics lists the resolved group, its source and every candidate tried; the check widget shows the group name.

Never hardcode the bundle ID, team prefix or group at runtime. No Keychain sharing: the widget never needs a key.
**If the App Group fails on device:** widgets can't read saved designs. Fallbacks to evaluate in M1/M3: bundle-only templates configured through the widget's AppIntent parameters (stored by the system, no App Group needed), and treating sideloaded builds as "templates only" until a paid account.

### ADR-005 — M0 capability probes (Diagnostics)
**Status:** Accepted (2026-10-20).
**Context:** The brief (§2) requires App Group, HealthKit, location in the widget and battery in the widget to be verified on a free-Apple-ID install before templates rely on them.
**Decision:**
- The widget extension writes a **widget report** (`Probe/widget-report.json`) on every timeline reload: heartbeat, whether it saw the app's heartbeat, `CLLocationManager.isAuthorizedForWidgetUpdates`, a location fix from inside the extension, and `UIDevice.batteryLevel`/state read inside the extension. The probe widget also shows these on the home screen, so they are visible even without a shared App Group.
- The app's hidden **Diagnostics** screen (long-press the version number in About; in M0 also a visible button) shows: build and profile info, App Group read/write, the widget report, location permission (When In Use, needed for `NSWidgetWantsLocation`), HealthKit (availability, authorization request, a steps query), app-side battery, and a shareable plain-text report.
- Each probe result is one of: ok, failed (with reason), not run.
- The app requests HealthKit read for step count and sleep analysis only (the bindings in brief §4.5).
- Outcomes go in a "Device findings" update of this ADR. Templates whose capability fails are dropped or rebound.

**Device findings (2026-10-20, M0 IPA, Sideloadly, free Apple ID):**
| Check | Result |
|---|---|
| Install, launch, widget in the gallery | ✅ the app installs; the widget appears and renders |
| Location inside the widget (`NSWidgetWantsLocation`) | ✅ fix received in the extension |
| Battery inside the widget | ✅ level readable in the extension |
| HealthKit | ✅ available in the app |
| Signing profile (`embedded.mobileprovision`) | ❌ **missing** in the installed bundle |
| App Group | ❌ **Shared ✕** in both the app and the widget: no group container is usable |

**Consequences:**
- Weather, prayer/Qibla, location and battery templates can work: the widget gets location and battery itself.
- Health templates can rely on HealthKit. Read access is a separate prompt, and a denial looks like "no data".
- **The app can't hand data to the widget on this install.** Saved designs, user photos, counters written by the app and the app's caches are invisible to the widget. M1 therefore renders **bundled specs** in the widget, chosen through the widget's AppIntent configuration, which the system stores without an App Group (see ADR-004). M3 has to design "My widgets" around this, or ship it only to installs where an App Group resolves.
- With no profile, the resolver only has the compiled ID and `ALTAppGroups` to try. AltStore/SideStore register `ALTAppGroups` on free accounts, so those installers may give a working group (ADR-004 order). Sideloadly with a free Apple ID doesn't.

### ADR-006 — Swift 5 language mode; CI compile-first, lint non-blocking
**Status:** Accepted (2026-10-20). Learned on Lakhas (ADR-019 there).
**Decision:**
- App, extension and `WidgetKitCore` build in Swift 5 language mode (`SWIFT_VERSION: 5.0`, `swiftLanguageModes: [.v5]`), minimal concurrency checking.
- **CI order** (amends brief §9 "SwiftLint → tests → IPA"): compile-only job first (continues after errors, full log artifact) → `WidgetKitCore` tests + UI smoke test → IPA. **SwiftLint** is a separate non-blocking job, because a lint failure first would hide compiler errors.
- Docs-only commits (`**.md`, `docs/**`) don't trigger the workflow. Superseded runs on the same ref are cancelled. SPM build data is cached.
- Claude reads failures with `gh run view --log-failed` and fixes all errors from a run in one commit; waits are foreground and capped at 8 minutes, no background watchers.

### ADR-007 — Secret scan before push
**Status:** Accepted (2026-10-20).
**Decision:** `scripts/secret-scan.sh` greps tracked files for API-key patterns (Anthropic, OpenAI, OpenRouter, Google `AIza`/`AQ.`, GitHub tokens, private keys). It runs as a pre-push hook (`git config core.hooksPath .githooks`) and as the first step in CI. The app ships no keys; user keys live only in the Keychain.

### ADR-008 — BYOK AI client ported from Lakhas (M5)
**Status:** Accepted (2026-10-20); implementation in M5.
**Context:** Lakhas (`KhaledZaki1919/lakhas`, `ios/LakhasKit/Sources/LakhasKit/AI/`) has a tested provider layer.
**Decision:** Port into `WidgetKitCore/AI/` (app only, never linked into the widget's code paths):
- `AITypes` (provider kinds, `AIRequest`, `AIError`, `AIProvider` protocol), `AIHTTP` (error mapping, one transient retry honoring Gemini's `retryDelay`), `AIDeadline` (hard deadline + cancellation, the timeout fix), `JSONValue`, `StructuredAI` (schema → provider → decode → `validate()` → one retry with the validation errors; prompt-only fallback when a provider rejects native schemas), `AIDiagnostics` (Last AI request, redacted).
- Providers: `GeminiProvider` (key only in `x-goog-api-key`, which makes `AQ.`-prefixed and `AIza` keys both work; `responseSchema` converted to Google's OpenAPI subset; thinking level low; `MAX_TOKENS` → truncated), `AnthropicProvider`, `OpenAICompatibleProvider` (OpenAI + OpenRouter).
- `AIKeyStore` (Keychain, sanitizes pasted keys: whitespace, invisible RTL marks, quotes, `Bearer `; format hints accept `AIza` and `AQ.`), `KeychainStore`.
- Changes for this app: default provider **Gemini** (Lakhas defaulted to Anthropic); features become `generateWidget` + `connectionTest`; the schema is `Spec/widget-spec.v1.schema.json`; `validate()` is the `SpecValidator`; drop price table / daily limit unless needed.

### ADR-009 — Spec v1 implementation choices (M1)
**Status:** Accepted (2026-10-21).
- **Decoding vs. validation:** `WidgetSpec` decodes leniently (unknown keys ignored). Unknown layer types decode as `.unknown` and unknown enum values (family, action, …) fail decoding. `SpecValidator.validate(data:)` turns either into a `SpecIssue` with a JSON path (`layers[3].action: unknown value`), never a crash. Validation returns the spec with frames clamped to the canvas (`Result<WidgetSpec, SpecIssues>`).
- **AI mode:** `SpecValidator(mode: .ai)` also enforces brief §5.1 (only `open.app` buttons, only time/date/weather bindings, font size ≥ 11). The exported `Resources/Spec/widget-spec.v1.schema.json` describes structure only; a unit test keeps its enums in sync with the Swift whitelists.
- **Additions to the brief's spec** (all optional):
  - `analogClock.timezone` (a timezone field or IANA name) for world clocks;
  - `dotBars.offColor`;
  - `labels` as comma-separated text or a binding;
  - literal values for `ring.progress` (`"0.4"`), `dotBars.values` (`"0.2,0.5,1"`) and `dotGrid.values` (`"0110…"`).
- **Binding kinds:** each binding yields text, number, levels, date or symbol. The validator checks the kind where it matters: `ring` needs a number, `dotGrid`/`dotBars` levels, `live.target` a date, `icon` a symbol.
- **Digits:** all bindings use Latin digits (also in Arabic), so they suit the `dot` font and never mirror. Weekday and month names follow the language (`ar_EG@numbers=latn`).
- **RTL:** the canvas is always laid out left-to-right in canvas units. In Arabic, only layers with `mirror: true` move to the mirrored frame and lay out their content right-to-left. `forecastRow` runs right-to-left in Arabic.
- **Circle templates:** with `background.outerColor`, the widget is filled with the outer color and the background is drawn as the largest centered circle.
- **Fonts:**
  - Doto ships as a variable font (default instance Black); its weight is set on the `wght` axis through CoreText.
  - IBM Plex Sans Arabic ships four static weights (Regular, Medium, SemiBold, Bold).
  - Fonts are registered per process (app and extension) and ship with their OFL licenses.
- **Buttons** are `Link`s to `widgetstudio://action/<action>?spec=<id>&arg=<value>` until the interactive AppIntents arrive (M4).
- **Data:** M1 renders `DataSnapshot.sample` (Cairo); real providers replace it in M4.
- **Widget:** the spec widget uses `AppIntentConfiguration` to pick a **bundled** spec, because the App Group doesn't work on Sideloadly installs (ADR-005). Its timeline follows the spec's `refresh`, and content margins are disabled so the canvas fills the widget.
